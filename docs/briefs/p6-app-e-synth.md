## Build

1. **A candidate that answers job questions.** The scripted candidate answers by coverage area and knows nothing of requirements. Add a model-played one for job interviews: given the persona, the requirement and the question, it answers in the persona's interview language, two to five sentences, as that person would talk, only from what the persona sheet holds (`facts` with their stories, the answers, `omit`). When the sheet holds nothing for the requirement it says so plainly ("I have not done that. The closest I have is ...") and never invents experience. `chatText`, role `bulk`, purpose `synth.job_answer`. For a follow-up it gives the missing piece if the sheet has it, otherwise says it has nothing to add. With no model configured, a plain fallback built from the sheet's stories.
2. **Applications for the simulated people** (`applications.ts`): for each demo company's job, the simulated people who are eligible for it (the `eligibility` rows the seed already makes) apply: at most two jobs per person and five people per job, chosen the same way every run. For each: `startApplication` in the persona's language with the consent, the loop over `submitApplicationTurn` until the closing line, `submitApplication`, then `assessApplication` directly (no queue). Through injected functions, as `SimDeps` does for the interview, so tests run on fakes. A run that the model failed (no assessment) is reported and left out, never stored half-done.
3. **Seed and snapshot**: the seed runs step 2 after people and Need Cards exist (not when restoring). Add `application` and `application_turn` to the snapshot's table list in the right order and to the restore, limited to simulated people. `applicant_ranking` is not snapshotted: after a reset no list is approved. `resetDemo` needs nothing new (the tables cascade from the person and the company); add a test that it leaves no application behind. `scripts/seed.ts` gets whatever option the seed needs to run or skip this step.
4. **The swap check** (`evals/application-swap/`, run by hand with `npx tsx`, real model, never in `npm run check`): take assessed applications from a database, put each one's answers into the other two languages with the model (role `bulk`, meaning kept, nothing added), rate each version with the product's own assessor input and prompt, and report per requirement whether the level moved, with a summary: how many ratings stayed, moved by one, moved by more. A README says how to run it and what a failure means. This is the check the pitch has been saying is not built.
5. **Tests** on fakes: who applies to what (caps, same choice every run); a whole simulated application reaches `assessed`; a failed run leaves nothing; snapshot and restore round-trip the two tables; reset removes them; the candidate's fallback never claims something the sheet does not hold.

## Watch out for

- Simulated people stay labelled as simulated everywhere; their applications are theirs like any other row of theirs.
- The simulated candidate is a test tool: its prompt may see the persona sheet, the product's assessor never does.
- Keep model calls few: one per answer, none for bookkeeping. The key allows 40 requests a minute for everything.
- Everything you call from the application feature comes from its `index.ts`.
